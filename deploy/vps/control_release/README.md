# Релиз кабинета: web + bot + siteapi

Отдельный путь для **обратно совместимого** релиза Python-кода и статического SPA на существующем управляющем хосте. Не использовать для удаления файлов/колонок, смены зависимостей, миграций данных, Compose, Caddy или VPN-нод. `add_server.py` и `update.py` для этого сценария не вызываются. Деплой не является zero-downtime: два процесса кратко пересоздаются.

## Собрать строго выбранное изменение

`cabinet-v1.json` — проверяемый список: четыре Python-файла (хэши до/после, `null` = нового файла ещё нет) и все необходимые входы `web/`, включая lock-файл и тесты. Изменения Gemini, счётчика IP, `landing/`, `.env` и другие файлы рабочей копии в контекст не попадают. Для следующего релиза делайте отдельный reviewed manifest; не обновляйте хэши автоматически при несовпадении. База для backend — **работающий образ каждого сервиса**, не устаревший git HEAD. Оператор отдельно подтверждает совместимость старого/нового приложения с одной актуальной БД.

Из корня репозитория, Python 3.10+, npm с Node 24, проверенное окружение сборки:

```sh
(cd bot && uv run --frozen --group dev pytest -q)
python3 deploy/vps/control_release/bundle.py deploy/vps/control_release/cabinet-v1.json /tmp/aegis-cabinet-v1
```

Сборщик проверяет входы, выполняет `npm ci`, тесты интерфейса/локализации и полную сборку в новом временном каталоге. При неудаче выходного каталога нет. Последняя строка — SHA-256 итогового `manifest.json`, **ID релиза**. Передавать следует именно собранный каталог и подтверждённый ID, а не пересобирать web на сервере. Хэш — контроль целостности, не цифровая подпись. Использовать только доверенные код, артефакты и SSH с проверкой host key.

Манифест артефакта версии 2 задаёт `service_files`: `bot` получает только свой обработчик и две службы импорта/подписки, `siteapi` — только `src/api/main.py`. Перед сборкой проверяются базовые хэши заменяемых файлов для данного образа. После сборки проверяется весь перечень: назначенные файлы должны иметь новые хэши, остальные — побайтно совпадать с работающим контейнером этого сервиса (включая отсутствие файла). Поэтому старый, но не затронутый релизом модуль соседнего сервиса не обновляется попутно. Общие исходники на диске всё равно должны совпадать с базой релиза. Старый артефакт v1 не получает новые правила задним числом.

Если меняется **только назначение файлов сервисам** для уже проверенного v1, не пересобирайте SPA: `__BUILD_STAMP__` в `vite.config.js` зависит от времени. Используйте `python3 bundle.py cabinet-v1.json НОВЫЙ_КАТАЛОГ --reuse-v1 КАТАЛОГ_ПРОВЕРЕННОГО_V1 --base-id ПОДТВЕРЖДЁННЫЙ_ID_V1`. Проверяются ID старого манифеста, все байты backend/web и хэш канонического исходного spec без `service_files`. Новый ID относится к новому манифесту, не к новой сборке frontend. При любом другом изменении этот режим неприменим.

## На управляющем хосте

Передать `host.py`, `bundle.py` и каталог артефакта в закрытый staging-каталог на **контроле**. Не размещать их в каталоге, который раздаёт Caddy. Указать фактический публичный hostname (без схемы/порта), `ID` — полные 64 hex-символа из сборки. Пути по умолчанию соответствуют `/root/aegis`. Следующие команды запускаются **отдельными шагами**, только после проверки цели:

```sh
python3 host.py prepare "$ID" --domain "$SITE" --bundle ./bundle
# Проверить state.json, старые/новые образы, список файлов, предыдущие страницы, план отката.
python3 host.py apply "$ID" --domain "$SITE"
# Только при необходимости отката:
python3 host.py rollback "$ID" --domain "$SITE"
```

- **prepare:** сверяет `/health`, `/api/locations`, RU/EN-страницы и входные ассеты через TLS Caddy; проверяет bind mount и соответствие запущенных контейнеров Compose; находит точные прежние образы, сверяет базовые файлы и на диске, и внутри обоих контейнеров. Делает защищённую копию заменяемых исходников/страниц и теги прежних образов. Готовит два образа-кандидата с отключённой сетью для `RUN`, компилирует код и проверяет хэши и импорты без боевых env, БД и доступа к сети. Работающие сервисы, теги Compose и публичные страницы не переключает. Если текущая статика или содержимое базовых образов отличается от ожидаемого, выяснить причину; не обходить защиту пересчётом хэшей вслепую.
- **apply:** заново проверяет сохранённые хэши, теги, Compose и ранее сохранённые страницы. Изменяет только выбранные исходники, теги и два контейнера (`up --force-recreate --no-deps --no-build --pull never bot siteapi`). После готовности бота и API публикует статику: ассеты первыми, HTML последним, каждый файл заменяется атомарно **внутри** существующего bind mount. Переключение трёх HTML-файлов не единая транзакция: старые ассеты сохраняются для открытых вкладок. Проверяет реальные ответы Caddy, а не просто наличие `index.html` на диске. Вход в кабинет с токеном пользователя не используется.
- **rollback:** возвращает прежние теги/образы, исходники и старые страницы без восстановления БД, env, пользовательских ключей и конфигов нод. Совместимость данных — предусловие. При ошибке после начала переключения вызывается автоматически. Если откат не завершился (например, потеря питания), состояние остаётся `switching`; после устранения причины выполнить `rollback` того же ID. Не применять более новый релиз поверх прерванного.

Проверка Compose: в версии 5.3.1 `config --hash` на исходном файле оставляет `env_file` нераскрытым, а `up` записывает метку с уже подставленным окружением. Поэтому сравнивается хэш модели из `docker compose config --format json`, повторно переданной Compose через stdin, с меткой работающего контейнера. Эта модель содержит значения env: её нельзя печатать или сохранять. Несовпадение по-прежнему блокирует `prepare`; изменение окружения между `prepare` и `apply` блокирует переключение.

Журнал и резервные файлы: `/root/aegis/control-releases/<ID>/`. `flock` исключает параллельные запуски **этого** инструмента. Старые скрипты этот замок не знают — не запускать одновременно, не менять Compose/env вручную во время операции. Для долгих команд использовать устойчивый терминал/супервизор. Теги/копии не чистить до закрытия окна отката; очищать по решению оператора. Старые и новые хэшированные ассеты могут сосуществовать. Файл с состоянием релиза не является снимком подписок.

## Проверка отказа локально

```sh
PYTHONPATH=. bot/.venv/bin/python -m pytest -q deploy/vps/tests/test_control_release.py
# Docker Compose v2, локально доступный python:3.12-slim, только тестовая машина:
AEGIS_RELEASE_DOCKER_TEST=1 PYTHONPATH=. bot/.venv/bin/python -m pytest -q deploy/vps/tests/test_control_release_docker.py
```

Тестовый Compose-проект имеет уникальные имена, не публикует порты и использует `network_mode: none`. Это учение с синтетическими сервисами, не запуск боевого Telegram-бота, не тест VPN и не проверка продакшен-домена.
