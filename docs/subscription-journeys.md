# Подписка: от оплаты до импорта, политика: от выбора до подтверждения

## Реализованный сценарий: подключить устройство из личного кабинета

Подписчик открыл кабинет после активации. Ему нужна **та же ссылка**, а не новая подписка. Кабинет читает собственный `/api/me`; кнопка копирует URL как текст. Ни просмотр, ни копирование не открывают этот URL. Только VPN-клиент при импорте запрашивает профиль. Сервис знает, что выдал конфигурацию, но это не доказательство установленного туннеля.

| Момент | До | После |
|---|---|---|
| Действующая, в том числе бессрочная подписка | Поле URL и кнопка без инструкции. «Скопировано» даже при отказе браузера. | «Подключить устройство»: какой URL скопировать, куда вставить, когда обновить список. Подтверждение после записи в буфер. При отказе поле выделено для ручного копирования. |
| Срок истёк, флаг `is_active` ещё не сброшен | `/api/me` сообщал `is_active: false`, но возвращал ссылку; сайт предлагал её скопировать. | Дата осталась, `sub_url: null`; приглашения импортировать нет. Чтение не отзывает доступ и не меняет запись в БД. |
| Клиент запросил сохранённую ссылку | Регистрация устройства шла до проверки срока; сборщик ссылок мог внезапно отозвать UUID и сделать commit. | Команда `prepare_subscription_import` проверяет срок **до** регистрации, сохраняя немедленный отзыв при таком запросе. Действующему клиенту с UA возвращается стабильный UUID устройства. Для распознанного приостановленного устройства конфигурация не выдаётся. Сборщик отклоняет истёкшую запись без записи в БД. |

`GET /sub/{token}`, `/sub-safe/{token}` и `/sub-fast/{token}` — существующий протокол клиентов, **не** API предпросмотра. Его HTTP-метод не менялся. На границе импорта допустимы обновление `Device`, синхронизация и отзыв; далее рендер получает конкретный UUID. Рендер без записи не означает рендер без ввода-вывода: для push-нод он по-прежнему читает шаблон у агента. Для клиентов без UA сохранён старый режим с UUID подписки. Публичные/legacy-ссылки, выбор Xray JSON или списка ссылок и заголовки подписки не менялись.

## Карта реальных путей

| Роль и шаг | Чтение | Изменение и владелец |
|---|---|---|
| Подписчик: начать и получить доступ | Бот показывает условия, тарифы и право на trial; сайт читает `/api/plans`, `/api/locations`. Публичный каталог — не список разрешённых локаций конкретного человека. | `/start` регистрирует пользователя/реферала; принятие текущей версии документов — отдельная команда. `handlers/user/subscription.py` активирует trial. Сайт начинает оплату (`api/checkout.py`); выдаёт доступ не редирект из банка, а обработка успешных Stars/Platega (`handlers/payment.py`, `services/payment_service.py`). |
| Подписчик: получить ссылку | `/subscription` проверяет пользователя, срок и доступные серверы. Кабинет после Telegram/TMA-аутентификации читает состояние из `api/main.py::_me_payload`. | Копирование в буфер — локальное действие. Перевыпуск — другая команда с подтверждением в настройках. Не подменять ей «подключить ещё одно устройство». |
| Подписчик: импортировать и проверить | Клиент обновляет список локаций. Бот показывает устройства в `/settings`, отдельно от срока подписки. Запрос профиля не равен VPN-сессии. | Импорт подготавливает устройство; приостановить/возобновить/удалить можно в `handlers/user/devices.py`, с проверкой принадлежности устройства подписке. |
| Подписчик: изменить маршрут | `handlers/user/locations.py` проверяет активность, доступ и Preview, показывает доступные варианты. Название формируется существующими `server_display_name`/`format_server_label`. | Выбор протокола/транспорта сохраняет предпочтение пользователя для локации. После обновления клиент получает его по прежнему URL. CDN добавляется как автоматический fallback в Xray JSON, не как ручная локация WL. |
| Админ: выбрать локацию | `/admin` → серверы (в том числе выключенные) → карточка конкретного `server.id` → «Доступ к Gemini». `handlers/admin/servers.py`, `keyboards.py`, `gemini.py`. | Просмотр не меняет политику. Отключить сервер, сменить режим доступа, выдать/отозвать доступ — отдельные команды с проверкой админа и согласованием состава клиентов. Скрыть из выдачи — не то же, что отозвать доступ. |
| Админ: сохранить и убедиться | Панель отличает отсутствие поддержки, «ожидается», ошибку и «применено». Кнопка обновления читает состояние; не сохраняет повторно. | `services/gemini_policy.py`: на активной поддерживаемой pull-ноде выбор сохраняется сразу, без «Применить»; проверяются capability и устаревшая форма. Decodo ограничен соответствующим админом, не становится политикой для всех. Публикуется поколение снимка. В `control/router.py` нода получает снимок и подтверждает поколение и digest через `/ack`. Успешный ack продвигает `applied_generation`; сравнение с `gemini_policy_generation` даёт статус, а не обещание в момент нажатия. |

## Целевой модульный монолит — предложение, не новая инфраструктура

Оставить общие модели и БД, а также раздельные точки запуска bot/siteapi. Граница модуля — решение, которым он владеет, а не используемый фреймворк. Адаптеры Telegram, сайта и планировщика должны вызывать одни и те же операции приложения.

| Модуль | Что ему принадлежит | Что отдаёт наружу |
|---|---|---|
| Аккаунт и согласие | идентификация, язык, бан, текущая версия документов | проверенный пользователь и право начать сценарий |
| Оплата и подписка | подтверждение платежа, trial, продление, истечение, явный перевыпуск | сведения для экрана: статус, срок, доступные действия; отдельно команды изменения |
| Устройства и выдача | регистрация/обновление устройства, приостановка, формат профиля | команда подготовки импорта; сборка профиля без изменений подписки |
| Каталог и доступ | локации, гранты, видимость и транспортные предпочтения | разрешённые для задачи локации: публичный каталог, личная выдача и админский список не взаимозаменяемы |
| Политики нод | допустимость изменения, желаемая конфигурация, публикация и подтверждение | «сохранено» и «подтверждено нодой» как разные состояния; не показывать настройки доступа/секреты в публичном API |

**Переход по вертикальным шагам:**

1. **Сделано здесь:** кабинет → инструкция → импорт. Изолирована команда подготовки, сборка профиля не меняет подписку. Без миграции таблиц, новой очереди или новых полей ядра.
2. **Следом — экран Telegram:** единый запрос сведений о подписке для кабинета и бота, не вызывающий `/sub`. Различать право на доступ и наличие видимых локаций: сейчас `render_subscription_screen` выбирает клавиатуру по наличию ссылки, поэтому при активной подписке без серверов может предложить «Купить VPN». В этом случае показать «Подписка активна. Доступных локаций пока нет». Для активной с локациями — «Подключить устройство»; подтверждение перевыпуска остаётся в настройках. Проверка: срок/бессрочность, бан, отсутствие локаций, чужой пользователь, Preview; ни одного нового устройства при просмотре.
3. **Затем — жизненный цикл и доступ:** переносить по одной команде (продление, отзыв, истечение) за общий прикладной интерфейс; сохранить блокировку выдачи и повторную обработку платежей. Для каждого переноса сравнивать до/после URL, UUID и выдачу на синтетических наборах (включая транспорт, одноимённые локации, Preview, каскад и CDN). Не менять сразу схему или формат клиента.
4. **Отдельно — админ:** собрать в карточке локации «что задано / что подтверждено», оставить немедленное сохранение. Проверки перехода: два админа со старой формой, недоступная capability, ошибка и повторный ack, разграничение Decodo. Использовать нынешний контур снимков; интеграцию с будущими событиями ядра начинать только после утверждения их контракта.

Платёж, фактическое установление туннеля и применение политики реальной нодой не моделируются как успешные результаты этого изменения. Тесты сценария: `bot/tests/test_subscription_import.py` (SQLite, ASGI и подмена вызовов агента), `web/src/App.test.jsx` (кабинет, буфер и ошибки браузера).

## Как проверить этот срез

Из `bot/` после `uv sync --frozen --no-install-project` (Python 3.14):

```sh
mkdir -p .codex_tmp
TMPDIR="$PWD/.codex_tmp" BOT_TOKEN=123:TEST ADMIN_IDS='[1]' GEOIP_ENABLED=false .venv/bin/python - <<'PY'
import sys
import pytest

def deny_network(event, args):
    if event in {'socket.connect', 'socket.getaddrinfo', 'socket.sendto'}:
        raise AssertionError('External networking disabled for local tests')
sys.addaudithook(deny_network)
raise SystemExit(pytest.main(['-q']))
PY
```

Результат в этой копии: **261 passed**, одно предупреждение FastAPI/Starlette об устаревшем использовании `httpx` в TestClient. Из `web/` после `npm ci`: `npm test -- --run` — **7 passed**, `node --test scripts/localize-dist.test.mjs` — **2 passed**, `npm run build` — сборка успешна. БД тестов временная, платежи и сетевые вызовы не нужны.
