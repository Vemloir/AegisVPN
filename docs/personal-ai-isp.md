# Personal AI ISP trial (Stockholm and Frankfurt)

An opt-in node-local trial for **one existing subscription**, using the same ISP proxy on both nodes. No additional subscription, provider API, public feature, pricing, DB migration, or credentials in bot snapshots/client profiles. The existing direct, Gemini DNS/WARP, and Decodo policy remains the base; this override wins only for the enrolled subscription and matching targets. No claim of region eligibility or access to features such as Dots.

- `agent/app/personal_ai.py` uses Xray's anchored `user` regex for the existing authenticated `user_<user>_sub_<subscription>` and its device/CDN suffixes. It also requires a VLESS inbound tag and a catalogued AI domain. Honest routing limits: Xray must know the domain; bare IPs/unknown SNI are not forced through the proxy. Authentication, app, API, media and region behavior need separate tests. In particular, this does not route all of Google, X, Facebook/Instagram or third-party sign-in.
- Catalog: ChatGPT plus OpenAI API/auth/assets hosts, Claude plus `anthropic.com` and all its subdomains, the explicit Gemini/AI Studio hosts, standalone Grok and xAI API, standalone Meta AI. Check missing first-party hosts before extending this list; do not add broad shared platform domains. The rule routes TCP/443 (including TLS WebSockets); matching UDP/443 is blocked so clients can use HTTPS over TCP rather than bypass this route via QUIC. This is HTTPS **inside** the VPN's XHTTP path: it is not an extra TCP/Vision entry or VPN transport change.
- Root-only profile `/data/node-control/personal-ai.json`: `user_id`, `subscription_id`, `address`, `port`, `username`, `password`. Generated from a private `socks5://` URL; no passwords in argv, logs, UI, or git. **Plain SOCKS5 does not protect proxy authentication on the upstream leg**. HTTPS to an AI site keeps normal end-to-end TLS; never disable certificate verification. Do not reuse the trial credentials for public service.
- Both rules use `ruleTag=personal-ai-isp`, and the SOCKS outbound uses the same tag. Guard and management rules remain before the override. Gemini/Decodo management recognizes its own rules; the override uses `full:gemini.google.com` so later Gemini changes do not replace it. Agent startup reapplies it after those policies. The existing private keys and identities are untouched by this feature.

## Rollout / disable

On the node, back up the live config and runtime image refs with root-only permissions. Validate a full candidate with that node's `xray run -test` before writing either live file. Verify that stripping only the two tagged rules and one outbound recovers the previous candidate. Do not run independent VPN or AI traffic probes on behalf of the user; native endpoint reachability and config validation do not prove the dispatched requests, provider authentication, or service acceptance.

For split Docker, the `xray-only` entrypoint supervises Xray as a child, not PID 1. The agent shares the Xray PID namespace: applying policies had previously killed the entire namespace on HUP, sometimes leaving the agent stopped. A release of this entrypoint needs a planned Xray and agent restart in that order; subsequent `pkill -HUP xray` should only respawn the data-plane process. Check the loopback `/health`, fresh desired/applied generation, and actual scoped rules. Keep unrelated services untouched. Updating the supervised image does not itself rotate client keys or enable other features.

To disable the trial without revoking access, back up, remove the node-local profile and only the tagged rules/outbound from **current** config, validate, then reload the Xray child in the supervised topology. Preserve the current client list and base Gemini policy, never restore a stale whole config after subscriptions changed. Document the applied state for operator rollback. Rerun domain tests before making product promises.
